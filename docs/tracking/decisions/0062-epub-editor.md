# 0062 — EPUB은 새 편집기에서 열고, 책 화면에서 고친 문단만 원본에 다시 쓴다

## 맥락

이음오피스는 PDF를 EPUB으로 내보내지만 EPUB 파일은 열지 못한다. 내보낸 책을 고치려면 다른 프로그램이 필요했다. `docs/tracking/status.md`의 남은 일에 "EPUB 열기와 번역"이 있었다.

EPUB은 zip 안에 장마다 XHTML 문서가 하나씩 든 형식이다. 책마다 만든 프로그램이 달라 표시와 스타일이 제각각이고, 이 앱이 모르는 요소가 많다. 원본 프로그램과 문서를 주고받을 수 있어야 한다는 규칙(저장 결과는 원본과 같아야 한다)을 EPUB에도 지켜야 한다. 사람이 읽는 계획은 `docs/plans/epub-editor.md`에 있다.

## 결정

- **1단계는 읽기, 글 고치기, AI다.** 저장소 주인이 골랐다(2026-10-24). 장 더하기·지우기·순서 바꾸기, 책 정보와 표지 고치기, 그림·표 넣기는 다음 단계다.
- **글은 보이는 책 화면에서 바로 고친다.** 저장소 주인이 골랐다. 대상이 누구나인 앱이라 코드(XHTML) 편집 화면을 기본으로 두지 않는다.
- **저장은 바뀐 블록의 범위만 원본 글에 바꿔 쓴다.** 장 전체나 책 전체를 다시 직렬화하지 않는다. 고치지 않은 블록·장·항목은 원본과 같은 내용으로 나간다. 바뀐 것이 없으면 파일을 다시 쓰지 않는다.
- **새 엔진 패키지(`packages/epub-engine`)와 새 편집기(`apps/epub`)를 만든다.** 셸에 붙이는 방식은 마인드맵 편집기와 같다. 새 의존성은 들이지 않는다(`jszip`, `zip-gate`, `saxes`).
- **책의 zip은 셸 뒷단에 한 벌만 둔다.** 화면은 장 글을 창구로, 자산을 `epub-asset://`로 받는다.
- **책의 스크립트는 돌리지 않는다. 원격 자원은 불러오지 않는다.**
- **DRM 책은 열지 않고 이유를 알린다.** 글꼴 감추기만 있는 책은 연다.
- **고정 배치 책은 읽기만 한다.**
- **Windows에서는 "연결 프로그램"에만 올린다.** 설치해도 EPUB의 기본 프로그램은 바뀌지 않는다.

## 택하지 않은 것

- **장 코드 편집 + 미리보기(HTML 편집기 방식).** 만들기는 가장 빠르지만 일반 사용자가 쓰기 어렵다. 필요해지면 2단계에 "원본 코드 보기"로 더한다.
- **Tiptap 같은 스키마 편집기로 장을 고치기.** 스키마 밖의 표시와 속성을 버린다. 원본 보존 규칙을 지킬 수 없다.
- **EPUB을 워드 문서로 바꿔 워드 편집기에서 고치기.** 되돌려 쓸 때 장 구조·스타일·이 앱이 모르는 요소를 잃는다. ODT 다리(결정 0034)와 달리 대응하는 문서 엔진이 없다.
- **읽기 전용 리더만 먼저 내기.** 저장소 주인이 "고치기"를 1단계에 넣기로 했다.
- **바깥 리더 라이브러리 들이기.** 그리기만 맡고 고치기는 못 한다. 블록 지도와 범위 바꾸기를 따로 만들어야 하는 것은 같다.

## 결과

- 셸에 새 문서 종류 `epub`이 생긴다. 탭 종류, MCP의 열린 문서 목록(`kind: "epub"`), 첨부 형식 목록에 들어간다(`docs/contracts.md`를 함께 고친다).
- `file-parse`가 EPUB 글을 뽑는다. 첨부, `@문서`, 파일 색인이 EPUB을 읽는다.
- "고치지 않은 부분은 원본 그대로"의 예외는 둘이다. 저장한 EPUB은 `mimetype`이 맨 앞에 압축 없이 놓인다(원본이 그 규칙을 어겼으면 저장으로 바뀐다). 바뀐 것이 있으면 OPF의 `dcterms:modified` 한 줄이 저장 시각으로 바뀐다.
- EPUB 번역, 쪽 넘김 보기, 명령줄 지원은 이 결정에 들어 있지 않다. 따로 계획한다.
