# 0075 Codex 구독 이미지 생성은 `codex exec` 한 번으로 넣는다

## 맥락

[0006](0006-no-codex-image-via-login-file.md)은 "로그인 파일을 건드리지 않는 방법으로만, 끝까지 확인되기 전에는 넣지 않는다"고 정했다. 그때는 이미지 도구가 없는 무료 계정으로 확인해 끝까지 가지 못했다.

그 뒤 Codex CLI에 ChatGPT 계정 이미지 생성(`image_gen`, gpt-image-2)이 들어왔고, 커뮤니티 스킬 `codex-image`가 그 경로를 문서화했다: `codex exec`에 "내장 image_gen으로 그려 파일로 저장하라"고 시키면 OAuth 로그인으로 이미지를 만들고, 파일을 프로젝트로 복사한다. 로그인 파일을 읽지 않는다.

## 결정

- Codex 이미지 생성은 **채팅 세션과 분리된 `codex exec` 한 번**으로 한다. 임시 폴더에서 `features.image_generation=true`, `workspace-write`, `--skip-git-repo-check`, `--ephemeral`로 실행하고, 생성된 이미지 파일을 읽어 기존 `generate_image` 경로로 넘긴다.
- 채팅 루프의 "구독 프로그램은 도구를 모두 끈다" 규칙은 그대로다. 이 호출은 대화가 아니라 그림 한 장을 위한 별도 실행이고, 임시 폴더 밖에는 쓰지 않는다.
- 로그인 파일(`~/.codex/auth.json`)을 읽거나 복사하지 않는다. 인증은 CLI가 스스로 한다.
- 그림 값은 로그인한 ChatGPT 요금제에 청구된다. 무료 요금제에는 이미지 도구가 노출되지 않았고, 그 경우 도구는 "이 세션에는 이미지 도구가 없다"는 문장을 돌려주고 앱이 끝날 때까지 그 경로를 숨긴다(요금제를 올리면 다음 실행에서 다시 시도된다).
- 앱이 시작할 때 `apps/docs`의 메인이 생성기를 등록하고 가용성을 켠다. 키 제공자가 있으면 그쪽이 우선이고, Codex 경로는 사용자가 고른 경우에만 쓴다(0002).

## 버린 대안

- **채팅 세션에서 Codex의 image_gen을 쓰게 한다**: 앱의 대화는 모든 내장 도구를 끄고 앱 도구만 쓰는 구조라, 이미지 도구 하나만 예외로 두면 대화 전체의 도구 통제가 무너진다.
- **로그인 파일을 복사해 별도 프로세스로 실행한다**: 동작은 알지만 배포 앱이 사용자의 로그인 정보를 복사한다. 0006이 금지한 길이다.
- **확인 없이 키 제공자로 몰래 넘긴다**: 사용자가 고르지 않은 요금 경로다.

## 결과

- 유료(Plus/Team/Enterprise) Codex 사용자는 키 없이 `generate_image`를 쓸 수 있다. 무료 계정은 명확한 안내와 함께 검색 이미지로 넘어간다.
- **유료 계정에서의 실제 생성은 이 PC에서 아직 확인하지 못했다**(Codex가 무료 계정). 단위 테스트는 가짜 CLI로 명령·파일 회수·실패 문장·임시 폴더 정리를 확인한다.
- `packages/ai-search/tests/codex-image-absent.test.ts`는 이제 "패키지 진입점만으로는 생성기가 등록되지 않는다"는 뜻이고, 앱의 등록은 `apps/docs`가 한다.
