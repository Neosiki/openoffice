# 0080 — AI 그림 넣기는 여섯 편집기에서 같은 세 가지 길을 쓴다

## 맥락

[0074](0074-ai-adds-new-pictures.md)에서 한글과 마인드맵에 "AI는 새 그림만 넣고 있던 그림은 건드리지 않는다"를 넣었다. 그때 워드와 HTML은 이미 사진 찾기·생성·채팅 첨부를 넣을 수 있었고, 엑셀은 사진 찾기·생성은 되지만 채팅에 붙인 그림을 넣을 길이 없었으며, 슬라이드는 세 길이 다 있었지만 파일 이름을 지시문에서 알려 주지 않았다.

사용자는 이 그림 넣기 방법이 엑셀·워드·한글·HTML·마인드맵에서 모두 같아야 하고 슬라이드도 같아야 한다고 했다.

## 결정

- 여섯 편집기(워드, 엑셀, 한글, HTML, 마인드맵, 슬라이드)는 모두 세 길을 제공한다.
  1. `image_search`로 실제 사진을 찾아 새 그림으로 넣기.
  2. `generate_image`로 그린 그림을 새 그림으로 넣기.
  3. 채팅에 붙인 그림을 새 그림으로 넣기.
- 새 그림 넣기는 있던 그림을 옮기지도, 크기를 바꾸지도, 바꿔치기하지도, 지우지도 않는다. 슬라이드의 `replace_image`처럼 있던 그림을 고치는 도구는 별개이고, 넣기 경로가 그것을 부르지 않는다.
- 채팅 첨부는 **정확한 파일 이름**으로만 가리킨다. 이름은 패널이 보여 준 목록에서만 경로나 바이트로 풀리므로, 모델이 임의의 로컬 경로를 가리킬 수 없다. 모델은 그림만 받고 파일 이름은 받지 않으므로, 각 편집기의 지시문이 그 대화의 그림 이름을 `attachedImageNote`(`@genoffice/agent-core`)로 한 줄 적는다. 이름이 없으면 아무것도 붙지 않는다.
- 엑셀은 `add_image` 연산에 `attachment`(파일 이름)를 받는다. `propose_operations` 전에 `resolveAttachmentImageOps`가 이름을 경로로 바꾸고, 바이트는 `readAttachmentImage`로 읽는다(로컬 파일 통로를 쓰지 않는다).

## 버린 대안

- **편집기마다 다른 도구 이름을 그대로 둔다**: 모델이 편집기 사이를 옮겨 다닐 때 같은 일에 다른 인자를 쓰게 된다. HTML의 `search_images`를 `image_search`로 맞춘 0074의 방향을 이어 간다.
- **첨부의 로컬 경로를 지시문에 적어 준다**: 모델이 경로를 그대로 `path`에 넣게 되어, 문서 속 글에 조종당하면 사용자가 붙이지 않은 그림을 읽을 수 있다. 이름 해석은 패널 목록 안에서만 한다.
- **첨부를 base64로 도구 인자에 넣는다**: 큰 JSON이 게이트웨이 유휴 제한에 걸리고, 모델이 그림을 다시 타이핑하는 사고가 난다(0074와 같은 이유).

## 결과

- 엑셀에서도 "이 사진 넣어 줘"가 채팅 첨부로 된다. 여섯 편집기의 지시문이 같은 이름 줄을 쓰므로, 사용자가 파일 이름을 말하지 않아도 모델이 정확한 이름을 고를 수 있다.
- 실제 구독과 빌드한 앱에서 엑셀 첨부 넣기, 각 편집기의 이름 줄이 보이는지는 아직 사람이 확인해야 한다.
