# 0082 — Claude의 문서 편집 차례는 응답 형식을 프로그램에 맡기고, 그 도구 하나만 허용한다

## 맥락

기본 AI 창은 Claude Code를 "한 차례짜리 두뇌"로 띄운다. 앱은 `{ text, toolCalls }` 형식의 답을 받아 도구를 직접 실행한다. 지금까지는 이 형식을 지시문의 글로만 요구했다. 프로그램의 `--json-schema` 옵션을 켜면 세션에 `StructuredOutput` 도구가 하나 붙는데, "Claude는 보고한 도구가 0개일 때만 진행한다"는 규칙 때문이었다.

2026-10-28 사용자가 "작업이 자꾸 중간에 멈추고, 생각하는 시간이 길다"고 알렸다. 대화 기록에는 모델이 도구 호출을 `text` 안에 자기 고유의 모양(`<invoke name="…">`)으로 쓰거나, JSON을 버리고 같은 줄(`</invoke>`, `<br>`)을 수만 번 되풀이한 답이 남아 있었다. 앱은 `{`가 없는 답을 도구 없는 마지막 답으로 받았다. 그래서 일이 끝나지 않은 채 멈췄고, 되풀이가 출력 한도에 닿을 때까지 몇 분씩 기다렸다.

0.12.7을 따로 빌드해 같은 조건(Claude 구독, Sonnet)으로 한글·워드·엑셀·PPT에 양식 채우기와 질의서 다듬기를 10번 보냈다. 끝까지 해낸 요청은 없었다. 정상 차례는 중간값 2.6초였고, 망가진 차례는 출력 9만~~13만 토큰에 6~~16분이 걸렸다. Opus는 빈 답을, Haiku는 형식 오류를 냈다. 같은 날 Codex로는 문제가 없었다. Codex는 형식을 app-server에 넘겨 답을 만드는 단계에서 강제한다.

같은 조건에서 `--json-schema`를 켜 보니, 프로그램이 보고한 도구는 `StructuredOutput` 하나였다. 모델은 그 도구를 자기 방식으로 불러 형식에 맞는 답을 냈고, 프로그램은 권한을 묻지 않고 스스로 확인 응답을 돌려줬다. 답은 결과 이벤트의 `structured_output`에 객체로 왔다.

## 결정

- 문서 편집 차례(`streamClaudeCodeCli`)는 `claudeCodeOutputSchema`로 만든 스키마를 `--json-schema`로 넘긴다. 스키마에는 앱 도구의 **이름만** 들어간다. 이름은 모델 API가 받는 모양(`^[A-Za-z0-9_-]{1,64}$`)이어야 하고, 아니면 프로그램을 띄우지 않는다. 사용자 글, 도구 설명, 입력 형식은 명령줄에 오르지 않는다.
- 그 차례는 프로그램이 보고한 도구가 **정확히 `StructuredOutput` 하나**일 때만 진행한다. 다음은 모두 지금처럼 `unsafe-tools`로 프로세스 트리를 끝낸다.
  - 다른 도구가 하나라도 더 있는 경우, 그 도구가 빠진 경우, MCP 서버가 붙은 경우
  - 다른 도구의 호출 조각이나 입력 스트림
  - `StructuredOutput` 호출의 확인이 아닌 도구 결과
  - 권한 요청
- 답은 프로그램이 확인한 `structured_output`을 먼저 쓰고, 없으면 그 도구 호출의 입력을 쓴다. 호출 밖에 쓴 글은 답으로 받지 않는다. 그런 차례는 형식 오류로 반복 처리의 다시 보내기 경로에 넘긴다.
- 모델이 앱 도구를 `toolCalls`에 넣지 않고 바로 부르는 일이 있다. 실제 구독 확인에서 편집기 지시문이 도구 이름을 말하자 모델이 `read_blocks`·`propose_operations`를 바로 불렀다. 프로그램에는 그 도구가 없어 "없는 도구" 오류로 돌려보냈는데, 모델은 이것을 "도구를 쓸 수 없다"로 받아들여 아무것도 고치지 않고 답했다(8번 중 3번). 그래서 이름이 그 차례의 앱 도구 목록에 있는 직접 호출은 **이번 차례의 요청으로 받는다.** `toolCalls`와 같은 검사를 거쳐 앱이 실행하고, 프로그램은 그 호출에 답하기 전에 끝낸다. 목록에 없는 이름은 지금처럼 거부한다. 지시문에도 앱 도구를 직접 부르지 말라고 적는다.
- 일반 대화(`chatClaudeCodeCli`)와 모델 목록 읽기는 지금처럼 도구 0개로, 스키마 없이 띄운다.
- CLAUDE.md·AGENTS.md 3번의 Claude 조항을 "보고한 도구가 정해 둔 목록과 같을 때만 진행한다(일반 대화와 모델 목록은 0개, 문서 편집 차례는 `StructuredOutput` 하나)"로 고친다.

## 버린 대안

- **지시문 방식을 두고 망가진 답만 수습한다**(되풀이를 일찍 끊어 다시 보내기, 가짜 호출을 진짜 호출로 바꾸기, 기록에서 빼기): 기다리는 시간은 줄지만, 모델이 형식을 어기는 일은 그대로라서 다시 보내는 만큼 시간과 한도가 계속 나간다. 글 속의 가짜 호출을 실행하는 것은 모델이 "호출하지 않기로 한" 글까지 실행할 위험도 있다.
- **도구 0개 규칙을 아예 없앤다**: `StructuredOutput`만 필요하다. 다른 도구를 막는 확인은 그대로 둔다.
- **스키마를 명령줄 대신 파일이나 표준 입력으로 넘긴다**: 지금 프로그램은 명령줄 값만 받는다. 이름만 담는 것으로 범위를 좁혔다.

## 결과

- 모델이 원래 쓰는 도구 호출 길로 답하므로, 글로 쓴 가짜 호출과 되풀이 출력이 생길 자리가 없어진다. 실제 구독 확인 결과는 `docs/tracking/status.md`에 적는다.
- `StructuredOutput`은 프로그램 안에서 답을 확인하고 돌려줄 뿐, 파일·명령·네트워크에 닿지 않는다. 이 도구를 허용해도 기본 AI 창이 할 수 있는 일은 늘지 않는다.
- 이 도구의 이름이나 동작이 프로그램 업데이트로 바뀌면 시작 보고 확인이 실행을 막는다(`unsafe-tools`). 그때 이 결정을 다시 본다.
- 관련 시험: `packages/ai-provider/tests/claude-code-cli.test.ts`("only the allowed tool, or no run", "the structured turn").
