# 0067 로컬 AI 연결 환경

## 맥락

폐쇄망·공공기관처럼 Claude·Codex 구독을 쓸 수 없는 곳에서도 이음오피스의 AI를 쓰려면, 사용자가 자기 PC나 사내망에서 돌리는 모델을 연결할 수 있어야 한다. 기존 `custom` 제공자는 주소·키·모델을 직접 적는 입력란뿐이라, 어떤 모델이 있는지, 문맥이 얼마나 되는지, 도구를 부를 수 있는지 알 길이 없었다.

사용자는 앱이 모델을 고르거나 권하지 않기를 원했다. 환경마다 쓸 수 있는 모델이 다르고, 앱이 기본값을 정하면 그 선택이 사용자의 환경과 맞지 않을 수 있기 때문이다.

## 결정

- 로컬 서버도 기존 `custom` 제공자를 그대로 쓰고 `kind: 'local'`로 구분한다. 새 제공자 id를 만들지 않는다.
- 설정 → AI에 "로컬 AI" 카드를 둔다. 서버 추가·수정·삭제, 모델 목록, 모델별 프로필, 연결 테스트만 맡는다. 모델을 내려받거나 추천·순위·기본 선택하지 않는다.
- 모델 프로필은 모델마다 `contextLength`, `maxContextLength`, `tools`, `vision`, 각 값의 출처(`server`·`user`·`test`), `checkedAt`, `notes`를 둔다. 사용자 값이 가장 세고, 모르는 값은 `false`가 아니다.
- `tools: false`가 확인되면 요청에 도구를 싣지 않고, 모델이 그래도 도구 호출을 내면 실행하지 않는다. 화면은 "글만 제안"을 알린다.
- 문맥의 80%를 넘으면 실행 한 번에 한 번 확인한다. 문맥을 모르면 4,096토큰으로 가정한다. 거절하면 모델을 부르지 않고 실행을 되돌린다.
- 서버마다 첫 응답 제한을 1~10분(기본 5분)으로 둔다. 기다리는 동안 화면이 `ping`을 보낸다.
- 서버 검색·연결 테스트는 사용자가 누를 때만 하고, 문서 내용을 싣지 않는다. 다른 서버나 클라우드로 자동으로 넘어가지 않는다.

## 버린 대안

- **새 제공자 id(`local`)**: 제공자 선택·라우팅·설정 표를 두 벌로 만들고, 기존 `custom`과 동작이 갈린다. `custom` 하나에 `kind`를 더하는 편이 작다.
- **Ollama 전용**: LM Studio·vLLM·사내 OpenAI 호환 서버를 못 쓴다. 발견만 Ollama API를 먼저 시도하고, 나머지는 `/v1/models`로 읽는다.
- **모델 추천·기본값**: 사용자의 환경을 앱이 알 수 없고, "앱이 고른 모델"이 책임 소재를 흐린다. 사용자가 고른다.
- **문맥 경고를 막지 않고 알리기만 하기**: 문맥을 넘긴 요청은 잘리거나 실패하고, 로컬 모델은 한 번의 실패도 오래 걸린다. 보내기 전에 멈춘다.
- **도구 지원을 모르면 끄기**: 모르는 것을 `false`로 두면 도구를 쓸 수 있는 모델도 글만 쓰게 된다. 모르면 그대로 보내고, 확인된 `false`만 끈다.

## 결과

- 설정 파일에 `kind`, `modelProfiles`, `timeoutMs`가 늘고, `customEndpoint: ''`가 "없음"을 뜻하게 됐다. 예전 파일은 첫 서버를 고르는 방식 그대로 읽힌다.
- 문맥 확인과 도구 끄기가 9개 편집기·홈 질문·PDF 문서 작업·EPUB 책 번역까지 이어져, AI 실행 경로마다 같은 규칙을 지킨다.
- 로컬 카드는 새로 만든 `kind: 'local'` 서버만 관리한다. 예전 `custom` 서버는 고급 설정에서 그대로 쓴다.
- 실제 Ollama·LM Studio·vLLM 서버와 화면 확인은 아직이다. 폐쇄망 배포, 모델 내려받기 도우미, 오프라인 모드, 감사 기록은 이번 범위 밖이다.
