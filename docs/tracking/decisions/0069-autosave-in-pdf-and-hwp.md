# 0069 PDF·한글의 자동 저장

## 맥락

문서 유형마다 자동 저장이 달랐다. PDF는 첫 수동 저장을 하기 전에는 자동 저장을 하지 않았고(읽기만 한 PDF를 지키려는 장치), 한글은 자동 저장 자체가 없어 30초마다 복구 사본만 남겼다. 사용자는 PDF도 처음부터 30초마다 저장하고 두 편집기 모두 화면에서 켜고 끌 수 있기를 원했다.

## 결정

- PDF와 한글도 다른 편집기와 같은 `useAutoSavePref` 토글과 설정 → 일반의 기본값을 쓴다. 그래서 처음에는 다른 편집기와 같이 꺼져 있고, 설정에서 켜거나 그 창의 토글을 켜면 작동한다.
- PDF는 첫 수동 저장 문턱(`savedOnceRef`)을 없앤다. 토글이 켜져 있고 문서에 경로가 있으면, 바뀐 내용을 30초마다와 창이 초점을 잃을 때 저장한다. 읽기만 한 PDF는 바뀐 것이 없어 쓰지 않는다. 읽기 전용 문서, Save As 흐름, 마스킹 사본, 저장 중에는 쉰다.
- 스킬 양식의 제목 없는 사본은 첫 수동 저장이 어디로 갈지 물어야 하므로 자동 저장에서 뺀다. 셸이 만든 빈 PDF(경로가 있음)는 자동 저장하고, AI가 고친 뒤의 조용한 저장도 토글이 켜져 있을 때만 한다.
- 한글은 저장할 파일이 있는 문서에서 30초마다와 창이 초점을 잃을 때, 입력이 약 2초 멈췄으면 저장한다. `commitSave`에 `automatic`을 보내 같은 파일을 나눈 다른 칸의 충돌에서 묻지 않고 물러난다. 제목 없는 새 문서와 스킬 양식 사본은 첫 저장 전이라 자동 저장하지 않는다.
- 한글 자동 저장은 성공 알림을 띄우지 않는다. 실패와 바탕쪽·메모 유실은 알리고, 실패 뒤에는 열 번(약 5분) 건너뛴다. 암호·변경 추적처럼 저장 자체가 불가능한 문서는 그 실패를 자동 저장에서 반복해 알리지 않는다.

## 버린 대안

- **PDF를 토글 없이 항상 저장**: 읽기용으로 연 문서를 실수로 고쳤을 때 사용자 모르게 원본이 바뀐다. 기본값은 꺼짐이고 화면에서 켠다.
- **PDF의 첫 수동 저장 문턱 유지**: 사용자가 요청한 동작과 다르고, 토글이 켜져 있다는 표시와 실제 저장 시점이 어긋난다.
- **한글 편집기(rhwp)의 IndexedDB 자동 저장 켜기**: embed 모드에서 되돌려 주지 않아 사용자 문서 사본만 앱 프로필에 쌓인다. 파일에 쓰는 앱 자체 자동 저장과 별개다.
- **한글 자동 저장을 복구 사본과 같은 주기로만**: 복구 사본은 원본 파일을 지키는 장치이고, 사용자가 요청한 것은 파일에 저장하는 자동 저장이다.

## 결과

- 두 편집기의 리본/상단 띠에 자동 저장 토글이 생기고, 설정 → 일반의 "모든 문서 자동 저장"이 9개 편집기 모두에 적용된다.
- PDF는 첫 수동 저장 전에도 자동 저장할 수 있지만, 제목 없는 사본은 여전히 첫 저장에서 위치를 묻는다.
- 한글은 문서를 내보내는 비용이 크므로 입력이 멈춘 뒤에만 자동 저장한다. 큰 문서에서 30초마다 저장이 도는 것이 부담이면 토글을 끈다.
