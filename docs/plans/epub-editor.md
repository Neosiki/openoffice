# EPUB 편집기 계획

상태: **초안**(2026-10-24). 범위와 고치는 방식은 저장소 주인이 정했다. "정한 것"은 결정 기록 [0062](../tracking/decisions/0062-epub-editor.md)에 옮겼다. 구현하면서 이 문서를 고친다.

## 1. 무엇을 하려는가

지금 이음오피스는 PDF를 EPUB으로 내보내기만 한다. EPUB 파일은 열 수 없다(`docs/tracking/status.md`의 "EPUB 열기와 번역"). 이 계획은 **EPUB을 탭에서 열어 읽고, 본문 글을 고치고, AI 창으로 읽고 고치게** 한다.

**정한 것**

1. 1단계는 읽기, 글 고치기, AI다. 장 더하기·지우기·순서 바꾸기, 책 정보와 표지 고치기는 다음 단계로 미룬다.
2. 글은 **보이는 책 화면에서 바로** 고친다. 코드(XHTML)를 고치는 화면은 1단계에 두지 않는다.
3. 저장할 때는 **바뀐 문단만** 다시 쓴다. 고치지 않은 문단, 장, 그림, 글꼴, 스타일은 원본과 같은 내용으로 남는다.
4. 새 편집기 하나(`apps/epub`)와 새 엔진 패키지 하나(`packages/epub-engine`)를 만든다. 셸에 붙이는 방식은 마인드맵 편집기와 같다.

## 2. 확인한 것 (2026-10-24)

- 저장소에 EPUB을 읽는 코드가 없다. 쓰는 코드는 `packages/pdf-structure/src/epub`(PDF → EPUB 3) 하나다. 이 앱이 쓴 EPUB은 배치가 일정하다(`OEBPS/` 아래 `content.opf`, `nav.xhtml`, `chapter-NNN.xhtml`, `images/`). 첫 시험 자료로 좋다.
- zip을 다루는 패키지는 모두 `jszip`을 쓴다. 압축 폭탄 검사는 `packages/zip-gate`가 한다. 위치 정보가 있는 XML 파서(`saxes`)와 HTML 파서(`parse5`)도 이미 작업 공간에 있다. **새 의존성 없이** 만들 수 있다.
- 가장 가까운 본보기는 마인드맵이다. 엔진(`packages/xmind-engine`)이 모르는 부분을 그대로 두고 바뀐 것만 맞춰 쓴다. 셸에 편집기를 붙인 자리는 약 60곳이다(11절).
- HTML 편집기(`apps/html`)는 코드 편집기 + 미리보기이고, 모든 편집을 원본 글의 범위 바꾸기(patch)로 한다. 이 "다시 직렬화하지 않는다" 규칙을 EPUB에서도 쓴다. 자산을 격리된 미리보기에 내주는 방식(`html-asset://`)도 같은 모양으로 쓴다.
- 워드처럼 고치는 편집기는 마크다운 편집기(Tiptap)뿐이다. Tiptap은 자기 스키마 밖의 표시를 버린다. EPUB 원본을 지키는 데 맞지 않아 쓰지 않는다(5절).

## 3. 범위

**1단계에 넣는 것**

| 영역   | 내용                                                                                                                              |
| ------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 열기   | EPUB 3과 EPUB 2. 탭, 열기 창, 끌어다 놓기, 최근 파일, 폴더 나무, Windows "연결 프로그램"                                          |
| 읽기   | 목차 창(EPUB 3 `nav`, 없으면 EPUB 2 `toc.ncx`), 장 넘기기, 글자 크기·줄 간격, 어두운 보기(화면만), 읽던 자리 기억, 책 안에서 찾기 |
| 고치기 | 문단·제목·목록 항목·인용·표 칸·그림 설명의 글. 문단 나누기·합치기, 굵게·기울임, 되돌리기·다시 하기, 책 전체 찾아 바꾸기           |
| 저장   | 같은 파일에 저장, 다른 이름으로 저장, 자동 저장(다른 편집기와 같은 설정), 닫기 확인                                               |
| AI     | AI 창: 책 구조 읽기, 장 읽기, 찾기, 문단 고치기. 보내기 전 판단·막힘 처리는 공용 부품                                             |
| 연결   | 첨부와 `@문서` 붙이기(글로 읽기), 파일 색인, MCP의 열린 문서 읽기·저장                                                            |

**1단계에서 빼는 것**

- 장 더하기·지우기·순서 바꾸기, 책 정보(제목·저자·언어)와 표지 고치기, 그림·표 새로 넣기 → 2단계.
- 쪽 넘김 보기. 1단계는 장마다 위아래로 흐르는 보기다.
- EPUB 번역(PDF의 문서 번역과 같은 작업), 명령줄(`ieumoffice`)의 EPUB 읽기·변환 → 따로 계획.
- 고정 배치(fixed-layout) 책의 고치기. 열어서 보여 주기만 한다.
- 저작권 보호(DRM)가 걸린 책. 열지 않고 이유를 알린다(4절).
- 소리·영상 재생, 책 안의 스크립트 실행.

## 4. 열기

엔진(`packages/epub-engine`)은 Electron에 묶이지 않은 TypeScript다. 셸 뒷단에서 돌고, 테스트는 node에서 한다. 책 하나의 zip은 뒷단에만 한 벌 둔다. 화면은 장의 글을 창구로, 그림·글꼴·스타일은 보호된 주소(`epub-asset://`)로 받는다. 큰 그림이 많은 책에서도 화면 프로세스가 책 전체를 들지 않게 하려는 것이다.

열기 순서와 거절:

1. `zip-gate`의 관문(`assertZipInflatesWithinLimits`, 선언 크기 검사). 걸리면 "파일이 손상되었거나 너무 큽니다".
2. `mimetype`이 `application/epub+zip`인지, `META-INF/container.xml`이 있는지. 순서·압축이 규칙과 달라도 읽기는 한다(많은 책이 그렇다). 저장할 때 바로잡는다(7절).
3. `META-INF/encryption.xml`에 글꼴 감추기(IDPF·Adobe 방식) 말고 다른 암호화가 있거나 `META-INF/rights.xml`이 있으면 **DRM 책**으로 보고 열지 않는다. 알림: "저작권 보호가 걸린 전자책은 열 수 없습니다. 구입한 서점의 앱에서 여세요."
4. OPF를 읽어 책 정보, manifest, spine, 목차 위치를 얻는다. `rendition:layout`이 `pre-paginated`이면 고정 배치로 표시하고 고치기를 끈다.
5. manifest의 경로는 OPF 기준으로 풀고, zip 바깥(`..`가 루트를 넘음)이나 스킴이 붙은 대상은 없는 것으로 친다. 원격 자원(`http(s)://`)은 불러오지 않는다.
6. 장은 열 때 모두 읽지 않는다. 화면이 그 장을 펼칠 때 읽는다. 찾기와 AI 읽기는 장마다 글만 뽑아 쓴다.

감춘 글꼴은 그리기용으로만 뒷단에서 풀어 내준다(알려진 공개 규격의 XOR). 저장할 때는 원본 바이트 그대로 둔다.

## 5. 고치기 — 원본을 지키는 방식

핵심은 **화면의 DOM을 통째로 저장하지 않는 것**이다. 장 하나를 다시 직렬화하면 속성 순서, 빈 요소 표기, 엔티티, 공백, 이 앱이 모르는 표시가 바뀌거나 사라진다.

1. **블록 지도.** 엔진이 장 XHTML을 위치 정보가 있는 파서(`saxes`)로 읽어 "고칠 수 있는 블록" 목록을 만든다. 블록은 인라인 내용만 가진 요소(`p`, `h1`~`h6`, `li`, `blockquote` 안의 글, `td`·`th`, `figcaption`, `dt`·`dd`, 글만 든 `div`)다. 블록마다 원본 글에서의 내용 범위(시작·끝 오프셋)와 블록 id를 가진다.
2. **그리기.** 화면은 장을 격리된 틀(iframe)에 책의 스타일로 그린다. 그리는 사본에서는 `script`와 `on…` 속성을 뺀다(원본은 그대로). 블록 요소에 `data-epub-block` id를 붙이고, 그 요소만 `contenteditable`로 만든다.
3. **고치기.** 고친 블록은 화면에서 그 블록의 안쪽만 XHTML 규칙으로 직렬화한다. 원본에 있던 인라인 요소(`span`, `a`, `ruby`, `sup` 등)는 속성까지 그대로 둔다. 새로 생기는 인라인 요소는 `strong`·`em`·`br`뿐이다. 붙여넣기는 글만 받는다.
4. **문단 나누기·합치기.** 블록 하나의 범위를 같은 요소 두 개로, 또는 이웃한 두 블록을 하나로 바꾸는 범위 바꾸기다. 새 블록은 원래 블록의 태그와 속성(`id`는 빼고)을 따른다.
5. **되돌리기.** 편집 기록은 블록 범위 바꾸기의 목록이다. AI의 한 차례 편집 묶음은 되돌리기 한 번이다.
6. **저장 전 검사.** 바꾼 장은 다시 XML로 읽어 잘 짜였는지 본다. 깨지면 저장하지 않고 그 장을 알린다. 이 검사에 걸리면 엔진의 결함이므로 시험으로 막는다.

`id`가 붙은 블록을 지우거나 합치면 그 `id`를 가리키던 목차·각주 링크가 끊긴다. 1단계는 합칠 때 앞 블록의 `id`를 남기고, 뒤 블록의 `id`는 빈 `span`으로 남긴다(링크가 그 자리로 간다).

## 6. 읽기 화면

```
┌ 리본: 파일 · 홈(굵게·기울임·찾기·되돌리기) · 보기(글자 크기·줄 간격·어둡게·목차) ┐
├──────────┬──────────────────────────────────────────────┬────────────┤
│ 목차     │  장 본문 (격리된 틀, 책의 스타일)              │  AI 창     │
│ · 1장    │                                              │            │
│ · 2장 ◀  │  문단을 눌러 바로 고친다                       │            │
│   · 2.1  │                                              │            │
├──────────┴──────────────────────────────────────────────┴────────────┤
│ 상태 줄: 장 3/12 · 바뀜 표시 · 고정 배치면 "읽기 전용"               │
└──────────────────────────────────────────────────────────────────────┘
```

- 장 끝에서 아래로 더 내리면 다음 장으로 넘어간다. 목차를 누르면 그 장의 그 위치로 간다.
- 글자 크기·줄 간격·어두운 보기는 화면에만 쓰는 스타일이다. 파일에 저장하지 않는다(`docs/standards.md` "화면 색": 책 내용의 색은 문서 자료).
- 읽던 자리(장과 블록)는 파일 경로마다 데이터 폴더에 기억한다. 책 파일에는 쓰지 않는다.
- 링크: 책 안 링크는 그 장·위치로 간다. 바깥 주소는 묻고 나서 기본 브라우저로 연다.

## 7. 저장

- zip을 새로 쓴다. 맨 앞에 `mimetype`을 압축하지 않고 둔다. 원본이 규칙과 달랐으면 이 저장으로 바로잡힌다.
- 바뀐 장은 블록 범위 바꾸기를 적용한 글로, 나머지 항목은 원본 내용 그대로 다시 넣는다. 항목 순서는 원본 순서를 지킨다.
- 바뀐 것이 있으면 OPF의 `dcterms:modified`(EPUB 3)만 지금 시각으로 고친다. 그 한 줄도 범위 바꾸기다. 바뀐 것이 없으면 저장 단추를 눌러도 파일을 다시 쓰지 않는다.
- 쓰기는 다른 편집기와 같은 원자적 쓰기와 바깥 변경 충돌 검사(`electron-utils/save-conflict.ts`)를 쓴다. 처음 열기가 성공한 파일에만 쓴다.

## 8. AI

AI 창은 다른 편집기와 같은 공용 부품(`packages/ui`, `packages/agent-core`)이다. 편집기 쪽 도구:

| 도구           | 하는 일                                                                                 |
| -------------- | --------------------------------------------------------------------------------------- |
| `read_book`    | 책 정보, 장 목록(제목·글자 수), 목차                                                    |
| `read_chapter` | 장 하나의 블록 목록(블록 id, 종류, 글). 긴 장은 나눠 읽는다                             |
| `find_text`    | 책 전체에서 글을 찾아 장·블록 id와 앞뒤 글을 돌려준다                                   |
| `edit_blocks`  | 블록 글 바꾸기, 블록 뒤에 문단 더하기, 블록 지우기. 글에는 굵게·기울임만 표시할 수 있다 |

- 매 차례의 맥락은 지금 장, 보이는 블록 범위, 선택한 글이다.
- `edit_blocks`는 사람이 고치는 길(5절)과 같은 길로 간다. 한 차례의 묶음이 되돌리기 한 번이다. 고정 배치 책에서는 도구를 주지 않는다.
- 책 글은 문서 데이터다. 그 안의 지시를 따르지 않는다는 지시문은 다른 편집기와 같다.
- 첨부·`@문서`·파일 색인은 `packages/file-parse`에 EPUB 글 뽑기를 더한다(spine 순서로 장의 글, 제목은 `#`). `attachable.ts`에 `.epub`을 넣는다.

## 9. 보안

- 책의 스크립트는 돌리지 않는다. 틀은 `sandbox`에서 `allow-scripts`를 빼고, 그리는 사본에서도 스크립트를 지운다.
- `epub-asset://`는 지금 열린 책의 zip 안 항목만 내준다. 응답에 바깥 연결을 막는 CSP를 붙인다. 원격 그림·글꼴·스타일은 불러오지 않는다.
- 파일 경로는 `..`가 zip 루트에서 멈추게 푼다. zip 관문을 거치지 않은 바이트는 엔진에 들어가지 않는다.
- 가리기(감추기) 표시는 1단계에 없다. EPUB에 가리기를 넣으려면 따로 정한다.

## 10. 파일 연결

`.xmind`처럼 Windows "연결 프로그램" 목록에만 올린다. 설치해도 EPUB의 기본 프로그램은 바뀌지 않는다. 파일 아이콘은 `tools/gen-file-association-icons.mjs`가 그린다(흰 문서, 등판 색, 책 기호. 결정 0052).

## 11. 셸에 붙이는 자리

마인드맵이 등록된 곳을 그대로 따른다. 큰 묶음만 적는다.

- 라우팅: `app-routing.ts`(확장자 → 편집기), `launch-paths.ts`(`LAUNCHABLE_EXTS`), `drop-open.ts`.
- 탭: `tab-manager.ts`(열기·바뀜 상태·닫기 확인·다시 열기), `window-close-guard.ts`, `detached-windows.ts`, `shared/tabs-api.ts`의 `DocumentTabKind`.
- 메뉴와 열기 창: `index.ts`의 열기 확장자, 필터, 메뉴 만들기, 21개 언어 메뉴 문구, 렌더러 프로토콜 등록, MCP 읽기·저장·모두 저장.
- 홈: 지원 형식 글, 필터, 아이콘(`Home.tsx`, `strings.ts`), 탭 아이콘(`TabBar.tsx`), 드라이브 목록.
- MCP: `mcp/tools/formats.ts`, `open-documents-tools.ts`, `open-documents-bridge.ts`(`docs/contracts.md`에 `kind: "epub"`을 적는다).
- 패키징: `electron-builder.cjs`(모듈 폴더, 파일 연결, 아이콘), `installer.nsh`(ProgId, 연결 프로그램 등록), 루트 `package.json`의 `dev`·`build:all`·`test`·`typecheck`, `tools/build-stale-preloads.mjs`.
- 새 문서 만들기 타일은 1단계에 두지 않는다. 빈 책을 만드는 일은 장 더하기와 함께 2단계다.

## 12. 문구와 도움말

- 편집기 문구는 `apps/epub/src/renderer/i18n/<영역>/<언어>.ts` 조각 파일로 21개 언어를 채운다. 한국어·영어는 직접 쓰고 나머지는 번역한다.
- 셸 메뉴·필터·홈 문구도 21개 언어.
- 앱 안 도움말에 "EPUB 읽고 고치기" 주제를 21개 언어로 더한다(`check:help-langs`).

## 13. 시험

- **엔진 단위 시험**(`packages/epub-engine/tests`)
  - 이 앱의 PDF → EPUB 결과, 공개 저작물 EPUB 3·EPUB 2 표본, 장 이름이 겹치거나 폴더가 깊은 책.
  - 아무것도 고치지 않은 저장: 모든 항목의 내용 바이트가 원본과 같다.
  - 문단 하나 고친 저장: 그 장의 그 범위만 다르고, 나머지 장과 항목은 같다. 바뀐 장은 잘 짜인 XML이다.
  - 나누기·합치기, `id` 남기기, 인라인 요소 보존, 엔티티와 CDATA, 공백만 있는 블록.
  - 거절: DRM 표시, 압축 폭탄, zip 밖 경로, `mimetype` 없음, OPF 없음.
- **화면 시험**: 블록 직렬화(인라인 요소 보존, 새 표시는 `strong`·`em`·`br`만), 붙여넣기는 글만, 되돌리기 묶음.
- **AI 도구 시험**: 가짜 모델로 `edit_blocks` 묶음 → 되돌리기 한 번. 실제 구독에는 닿지 않는다.
- **개발 PC 확인**: 고친 파일을 `epubcheck`로 검사해 오류 0(시험 의존성이 아니다. `pdf-structure`와 같은 방식). 다른 전자책 뷰어에서 고친 책을 열어 본다.
- **사용자 확인**: 빌드한 앱에서 실제 책 열기·고치기·저장, AI로 문단 고치기를 실제 구독으로 한두 번.
