# apps/mindmap (`@genoffice/mindmap`)

마인드맵 편집기다. `.xmind` 파일을 열고 고치고 저장한다. 지도를 그리는 일은 mind-elixir(`5.15.1`로 고정)가 하고, 파일을 다루는 일은 `packages/xmind-engine`이 한다. 이 모듈은 둘 사이를 잇는다. 화면에 보이는 이름은 "마인드맵"이다.

## 맡은 범위

- 렌더러(`src/renderer/`)
  - `document/`: 엔진의 보기용 자료와 mind-elixir 자료 사이의 변환(`convert.ts`), 열려 있는 지도 하나(`session.ts`: 엔진 문서, 시트 목록, 시트별 되돌리기 기록, 저장할 바이트), 열기(`open.ts`), 시트 지우기 전의 확인(`sheet-actions.ts`), 저장 때 넣을 미리보기 그림의 자리(`thumbnail.ts`).
  - `map/`: 시트 하나를 그리는 `MapController`(`controller.ts`), 파일에서 온 글이 HTML이 되지 않게 하는 장치(`text-guard.ts`), 지도 모양(`look.ts`).
  - `components/`: 도구 줄, 시트 탭, 대화 상자와 안내, 직접 그린 그림.
  - `i18n/`: 21개 언어 문구(`app/<언어>.ts`)와 mind-elixir 메뉴 문구(`map-strings.ts`).
- 메인 프로세스(`src/main/mindmap-main.ts`): 파일 읽기·쓰기, 뷰마다 허용된 경로, 닫기 전 저장 확인, 이름 바뀜 따라가기, 링크 열기, 단독 실행.
- IPC 계약 `src/shared/ipc.ts`(`MINDMAP_CHANNELS`). 이 편집기가 갖는 창구 이름과 주고받는 자료의 모양이 전부 여기 있다. 아직 받는 쪽이 없는 창구에는 맡을 작업이 주석으로 적혀 있다.

## 맡지 않는 것 (경계)

- `.xmind` 파일의 해석, 보존, 맞추기, 개요 글, 테마 표는 `packages/xmind-engine`의 범위다. 엔진에 문제가 보이면 여기서 돌려 막지 않는다.
- 탭, 창, 메뉴, 홈 화면, 열기·저장 대화 상자의 확장자 목록은 `apps/shell`의 범위다. 이 모듈은 shell이 부르는 함수(`createMindmapView`, `requestMindmapSave`, `requestMindmapClose`, `sendMindmapMenuCommand` 등)를 내보낼 뿐이다.
- 공용 `ai:*` 창구와 구독 창구는 `apps/docs/src/main/docs-main.ts`가 등록한다. 이 모듈은 등록하지 않는다. preload는 그 창구를 부르기만 한다.
- 화면 틀의 색(토큰)은 `packages/ui`의 범위다.

## 항상 지켜야 하는 것

- **모르는 요소를 버리지 않는다.** 편집기가 보여 주지 않는 것(경계, 떠 있는 토픽, 말풍선, 요약 아래 가지, 모르는 키)은 원본 나무에 그대로 남는다. 화면의 상태로 원본 나무를 통째로 다시 쓰는 길을 만들지 않는다. 바뀐 것은 엔진의 `reconcileSheet`가 화면 상태와 비교해 적는다.
- **바뀐 것이 없으면 저장 결과는 원본 바이트 그대로다.** 열기만 한 지도, 고쳤다가 되돌린 지도가 여기에 든다. 되돌리기는 시트의 원본 나무 사본을 제자리에 넣되 문서를 "바뀜"으로 표시하지 않는다(`session.ts`의 `restoreSheet`). 엔진의 `replaceSheet`는 문서를 바뀜으로 표시하므로 되돌리기에는 쓰지 않는다.
- **`ok`로 열리지 않은 파일에는 쓰지 않는다.** 경로가 저장 대상이 되는 것은 메인 프로세스가 그 파일을 엔진으로 직접 열어 `ok`를 본 뒤다. 경로를 받아 만든 뷰는 저장 대상 없이 시작하고(`unopenedByWc`), 그 파일이 여기서 열리기 전에는, 그리고 열리지 않았다면 끝까지, 저장 호출·메뉴 저장·닫기 확인·지정 경로 저장(`mindmapSaveToPath`)이 모두 거절된다. 다른 이름으로 저장도 마찬가지다. 화면이 무엇을 보내든 보내지 않든 달라지지 않는다. 저장으로 넘어온 바이트도 지도로 열릴 때만 쓴다.
- **파일에서 온 글을 HTML로 해석하지 않는다.** mind-elixir는 요약과 연결선의 글을 `innerHTML`로 넣는다. 끌 수 있는 유일한 자리가 `markdown` 옵션이라, 여기에 글자를 escape만 하는 함수를 넣어 모든 글이 그 함수를 거치게 했다(`text-guard.ts`). 이 옵션을 빼거나 실제 마크다운 변환기로 바꾸면 요약·연결선 글이 그대로 HTML이 된다. 노드에는 `dangerouslySetInnerHTML`, `hyperLink`, `image`, `icons`, `style`을 주지 않는다(`convert.ts`가 지운다). 클립보드에서 붙여 넣은 노드는 그리기 전에 씻는다.
- **링크는 모두 글자로 보이고, 여는 것은 메인 프로세스뿐이다.** 토픽의 링크는 주소가 무엇이든(`javascript:`, `file:` 포함) 파일에 있는 그대로 토픽에 글자 조각(span)으로 보인다. 앵커로 만들지 않고 mind-elixir의 링크 요소(`hyperLink`)도 쓰지 않는다. 화면은 `openLink` 창구로 주소를 넘길 뿐이고, 메인 프로세스가 `safeExternalUrl`을 통과한 주소(http, https, mailto. `src/shared/links.ts`)만 연다. 통과하지 못한 주소는 눌러도 열리지 않고 파일의 값은 그대로 남는다. 사용자가 적은 주소도 같다. 저장하고 글자로 보이며, 열리지 않을 주소면 대화 상자가 미리 알린다. 다른 토픽이나 첨부를 가리키는 꼴(`xmind:`, `xap:`)만 받지 않는다. 그런 링크는 보이지 않고 보존만 되는 것이라, 적으면 화면에서 사라지기 때문이다.
- **화면과 원본 나무가 어긋나면 원본 나무가 이긴다.** 맞추기가 거절했거나(`ok: false`), 맞춘 뒤의 모습이 화면과 다르면(`inSync: false`) 원본 나무의 보기용 자료로 다시 그린다.
- **지도를 고치는 길은 `MapController`의 편집 함수 하나다.** 도구 줄, 단축키, 메뉴, AI가 모두 같은 함수를 부른다. 여러 편집을 한 번에 넣거나 접혀 있어 요소가 없는 토픽을 고칠 때는 `edit()`를 쓴다. 원본 나무에 직접 쓰는 것은 시트 탭(추가·이름 바꾸기·삭제)뿐이다.
- **시트 삭제와 보이지 않는 요소가 딸린 삭제는 먼저 묻는다.** 시트 삭제는 되돌릴 수 없다고 밝힌다. 마지막 시트는 묻지 않고 거절한다. 사람이 아닌 호출자(AI)는 `'refuse'`로 불러, 묻는 대신 거절과 개수를 받는다.
- **지도의 색은 문서 내용이다.** `look.ts`와 `map.css`는 화면 틀 토큰을 참조하지 않고, 앱의 밝게·어둡게를 따라가지 않는다. 지도 위에 편집 중에만 그리는 것(선택 틀, 입력 상자, 지도 메뉴)은 화면 틀이라 `styles.css`에서 토큰으로 칠한다.
- **창구 이름은 `mindmap:`으로 시작한다.** `src/shared/ipc.ts`에 이미 있는 이름을 쓰고, 받는 쪽이 준비된 창구만 등록한다.
- 화면에 "XMind"라고 적는 곳은 "XMind 파일(.xmind)을 열고 저장한다"는 호환 설명뿐이다. 다른 프로그램의 이름·색·그림·글꼴·예제 파일을 저장소에 넣지 않는다. 테스트용 지도는 테스트 코드가 엔진으로 만든다.

## 이 모듈의 방식

- 지도는 화면 쪽에 있다. 화면이 엔진으로 바이트를 열어 문서를 쥐고, 고칠 때마다 맞추고, 저장할 바이트를 만들어 메인 프로세스에 넘긴다. 메인 프로세스는 임시 파일에 쓴 뒤 바꿔치기한다.
- 시트마다 mind-elixir 인스턴스를 하나씩 둔다. 시트를 처음 볼 때 만든다. 되돌리기 기록이 시트끼리 섞이지 않는다.
- 되돌리기는 mind-elixir의 기록을 쓴다. 맞추기는 결과만 보므로, 지운 토픽을 되돌릴 때 화면 상태만으로는 그 토픽이 지녔던 보이지 않는 것을 살릴 수 없다. 그래서 기록의 단계마다 시트 원본 나무의 사본을 두고(`session.ts`), 되돌릴 때 그 사본을 넣은 뒤 화면과 견준다. mind-elixir가 기록을 남기는 것은 `operation` 알림이 올 때뿐이다. 접기와 배치는 기록에 없고, 시트 이름·테마·배치는 되돌리기가 건드리지 않는다.
- mind-elixir는 요약과 연결선을 스스로 잊는다(범위가 맞지 않게 된 요약, 끝을 그릴 수 없는 연결선). 파일이 그것 때문에 잃으면 안 되므로, 마지막 보기용 자료에 있던 요약과 연결선은 사용자가 지웠을 때만 상태에서 뺀다(`convert.ts`의 `mindToState`).
- 새 토픽·요약·연결선의 식별자는 파일이 쓰는 꼴(UUID)로 만든다. 라이브러리가 만든 식별자는 기록에 남기 전에 바꾼다(`controller.ts`의 `#prepare`). 그래서 맞추기가 식별자를 바꿀 일이 없다.
- 라벨·메모·링크는 노드의 `metadata`에 있고, 화면의 꼬리표(`tags`)는 거기서 만들어 낸 표시일 뿐이다. 값을 읽을 때 `tags`를 읽지 않는다.
- 배치는 사용자가 도구 줄에서 골랐을 때만 파일에 적힌다. 라이브러리의 Ctrl+방향키 배치 전환은 막았다.
- 저장할 때 미리보기 그림을 넣으려면 `setThumbnailProvider`에 만드는 함수를 건다. 없으면 파일의 그림이 그대로 남는다.
- 잘라내어 같은 시트에 붙이면 옮기기다. 잘라낼 때 원본 토픽의 사본을 쥐어 두었다가, 클립보드에 그 토픽들이 그대로 있을 때 붙이면 원본 토픽을 통째로 되넣는다(`session.reinsertTopics`. 식별자, 모르는 키, 보이지 않는 가지, 함께 지워졌던 연결선까지). 두 번째 붙이기, 다른 시트나 다른 문서에 붙이기, 복사해 붙이기는 보이는 값으로 새 토픽을 만든다. 다른 것을 복사하거나 잘라내면 쥐어 둔 사본을 버린다.
- 제목을 치고 있는 입력 상자는 포커스를 잃을 때에야 지도에 들어간다. 그래서 저장하거나 지도를 읽어 주기 전에는 열려 있는 입력 상자를 먼저 넣는다(`commitEdit`. `App.tsx`의 `flushAll`). 조합 중인 글자는 브라우저가 포커스를 옮기며 확정하므로 남는다. 30초 자동 저장은 치는 도중의 입력 상자를 닫지 않고 그 차례를 건너뛴다. 입력 상자 안에서는 Ctrl+방향키를 막지 않는다.
- 메인 코드는 shell 번들에 들어간다. `src/main`을 고친 뒤에는 shell을 다시 빌드한다.
- 문자열은 `src/renderer/i18n/app/`의 언어별 조각이고 `zh.ts`가 키 집합을 정한다. 21개 언어 모두에 넣는다.

## 테스트

- 실행: `npm run test -w @genoffice/mindmap`, `npm run typecheck -w @genoffice/mindmap`. Windows에서 전부 통과한다.
- 환경은 jsdom이다. 실제 mind-elixir를 그대로 돌린다. jsdom에 없는 것(`innerText`, `matchMedia`, 포인터 잡기)과 형식 배열의 종류 차이는 `tests/setup.ts`가 메운다.
- 바꾸면 반드시 테스트하는 것: 열기만 한 지도가 "바뀜 없음"으로 맞춰지는지(`tests/convert.test.ts`), 지운 뒤 되돌리면 원본 나무가 글자 그대로 돌아오고 저장이 원본 바이트인지(`tests/session.test.ts`, `tests/controller.test.ts`), HTML처럼 생긴 글이 요소를 만들지 않는지, 열리지 않을 주소가 글자로 보이고 파일 값이 그대로인지, 잘라내어 붙인 토픽이 원본 그대로 도착하는지, 여기서 열린 적 없는 파일에 어떤 저장 길로도 쓰지 않는지와 링크 거절(`tests/main.test.ts`), 삭제 확인이 뜨는 조건과 치던 제목이 저장에 들어가는지(`tests/app.test.ts`).
- 빌드한 앱을 실제로 몰아 보는 확인은 `tests/real-run/driver.ts`다. `npm test`에는 들어 있지 않다. 한글 조합 입력, 끌어 옮기기, 저장 후 다시 열기, 큰 지도의 속도를 본다.
